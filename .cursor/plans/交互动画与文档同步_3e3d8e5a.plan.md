### 1.2 手动视觉 QA 清单（1280px + light/dark）

窗口宽度固定 **1280px**（DevTools device toolbar 或 resize）。每个 Topic 在 **light + dark** 各过一遍。

| Topic | Demo kind | 检查点 |
|-------|-----------|--------|
| T01 | `stack_compare` | 栈层按钮 `scrollWidth ≤ clientWidth + 2px`；bridge 文字不叠层；点击层级两侧 `active` 同步；自动演示 step 与 layer 索引一致 |
| T02 | `kv_paged_attention` | 24 格 block 墙不撑破 `.cache-wall`；`writing`/`shared`/`used` 三种态可辨（见 1.5 色盲安全要求）；负载滑块改变 `used` 块数 |
| T03 | `batching_prefill` | 5 行网格 cell 对齐；step 0 → step 1：`.batch-cell.stalled` DOM 计数 **24 → 0**（见下「T03 stalled 计数约定」）；scan-line 不遮挡行标签 |
| T04 | `ascend_operator` | tile 在 CopyIn→Compute→CopyOut 流动；负载 20% vs 100% 时 tile 数量差 ≥1；zone `active` 与 `activeStep` 一致 |
| T05 | `distributed_inference` | step 0 时 packet 节点数 = 0；step ≥1 时 packet 节点数 = 3；step 3 时 decode 节点带 `.routing` class |

**跨 Topic 共性（1280px media query 须补全）**：

- `.interactive-head` / `.interactive-control` 堆叠后无横向溢出
- `.interactive-stage` 单列后 `.metric-grid` 改为 1–2 列
- `.interactive-steps` 按钮可点击区域 ≥ 44×44px（WCAG 2.5.5 目标尺寸）

### 1.3 五类 Demo 动效打磨

在 **已 checkpoint 的 WIP** 上做最小增量；不重构 schema、不引入 Canvas 库。

**T01 `StackCompareVisual`**
- 确认 `playing` 时 `activeStep % left.length` 与 layer 高亮一致
- bridge `.bridge-line` 在 layer 切换时重播 `bridge-flow`（CSS animation reset）

**T02 `KvPagedVisual`**
- step 切换时 token-lane 高亮（`index <= activeStep`）与 block `used` 计数同步
- `writing` 态：边框 + 缩放动画；`shared` 态：虚线边框或角标（不只靠色相）

**T03 `BatchingVisual` — stalled 计数约定（实施前先 Read 确认）**

源码 [`batchPattern(0)`](../../src/renderer/components/InteractiveLesson.tsx) 中 `stalled: [3,4,5,6,7,8]` 是 **6 个列索引**；[`BatchingVisual`](../../src/renderer/components/InteractiveLesson.tsx) 对 R1–R4 四个 decode 行各渲染 12 列，列索引命中则该 cell 带 `stalled` class。

- **列索引层**：step 0 有 6 列 stalled、step 1 有 0 列（`batchPattern` 唯一真相）
- **DOM 层（验收用）**：step 0 时 `.batch-cell.stalled` 节点数 = **6 × 4 = 24**；step 1 时 = **0**
- 实施者须在首次 QA 时用 DevTools `document.querySelectorAll('.batch-cell.stalled').length` 核实上述 24/0；若渲染逻辑变更，以实测 DOM 数为准并同步更新本 plan 与测试断言

其他 T03 任务：
- step 切换时为新增 `.batch-cell.on` 触发 `cell-pop`

**T04 `AscendOperatorVisual`**
- step 0 默认高亮 CopyIn（`activeZone = 0`），避免三区全灰
- 负载 100% 时 tile 不溢出 `.pipeline-track`（`getBoundingClientRect` 不超出父容器 + 2px）

**T05 `DistributedInferenceVisual`**
- step 3 时 decode 节点 `.routing` 有 border/glow（不只改文字）
- step 0 隐藏 packet（已实现，QA 确认 DOM 节点数）

**指标与动画一致性原则（禁止造假）**

- 指标必须反映 **当前 step / intensity 驱动的真实计算逻辑**，不得为「让数字看起来在变」而调 `buildMetrics` 的 base 系数
- 若某 step 对某指标无物理意义的变化：**该 step 下该指标显示 `—` 或固定为 seed 声明的基准值**，并在 explainer 中说明为何不变化
- 若整个 demo 的 step 设计无法让指标合理变化：**重排 step 或调整 `buildMetrics` 公式**（改公式逻辑，不是改 magic number 骗视觉）
- 负载滑块只影响 demo 中 **确有负载语义** 的变量（KV 块数、tile 数量、transfer 宽度等），指标须从同一变量派生

### 1.4 测试补强（锁住核心不变量）

现有 [test/renderer.test.tsx](../test/renderer.test.tsx) 保留；**新增以下用例**（目标：测试数 43 → ~50，仍不引入 Playwright）：

  1. `interactive-explainer strong` 文本 === `steps[i].label`

**B. Topic 切换卸载**

- App 中 T01 → T02 → T01：断言 region `aria-label` 切换、旧 demo 的 step 状态重置（T02 的 step 0 而非继承 T01 的 step 3）

**不测**：CSS keyframe 像素、动画帧率（实窗 + 1.5 性能/a11y 节负责）
