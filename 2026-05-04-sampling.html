采样的几何：当 logits 被四把刀切开

Temperature、top-k、top-p、min-p——每一个都不是「模型参数」，而是一把把切割概率分布的刀。理解它们形变分布的方式，比记公式更接近产线直觉。

I.为什么这是产线问题 II.温度：分布的拉伸 III.top-k 的硬边界 IV.top-p 的动态边界 V.min-p 的尺度感知 VI.四把刀同时挥
I.

为什么采样是产线问题

推理工程师的注意力大部分被 TTFT、TPOT、throughput 占据。但用户体感的「这模型靠不靠谱」很多时候不在延迟，而在下一个 token 的概率分布被怎么裁剪了。同样一个 70B 模型，temperature=0.2, top_p=0.9 和 temperature=1.0, top_p=0.95 出来的产物气质完全不同——前者像谨慎的研发主管，后者像爱发散的产品经理。

这四把刀——temperature、top-k、top-p、min-p——位于 logits 出来之后、采样之前那一小段流程里。它们的成本几乎为零（vocab 维度的一次 sort + mask），但对输出质量的影响远大于一次微调实验。

本节我们用一个固定的 logits 分布（来自一段 prompt 的真实模型输出，30 个候选 token）作为对照样本。每一节给你一把刀去切它，盯着柱状图变化，建立直觉。

核心立场。采样参数不是「玄学」。它们是分布几何的精确操作：每一把刀对应一个明确的可视形变。看清形变，参数就调得动。
II.

温度：把分布拉宽或压窄

温度 T 在 softmax 之前除 logits：p_i = softmax(z_i / T)。T < 1 把分布往最大值压（变得更确定），T > 1 把分布拉平（变得更随机）。T → 0 退化成 argmax（贪心），T → ∞ 退化成均匀分布。

关键：温度不会改变 token 之间的相对排名，只改变它们的相对差距。第一名永远是第一名，但第十名能不能咬上来全看 T。

记忆点。温度调的是第一名的统治力。T=0.7 是大多数产线的默认起点，因为它既保留确定性，也留出一点尾部多样性——但它对长尾的衰减仍然是指数级的。要真正切掉长尾，得靠 top-k / top-p / min-p。
III.

top-k：硬边界，不看上下文

top-k 把分布按概率降序排序，只保留前 k 个，剩下的 mask 成 0，再把存活的归一化。它的好处是简单、快、可预期；缺点是 k 是个绝对数字，对不同的 token 分布不公平。

设想两种情况：（a）模型对下一 token 极有信心，top-1 占 95%；（b）模型很犹豫，分布很平。k=40 在 (a) 几乎是「冗余的安全网」（多保了 39 个噪音），在 (b) 又可能太严格（裁掉了真正有意义的候选）。

记忆点。top-k 是「一刀切到第 k 名」，不知道自己切的是肉还是骨。它对低信心分布过严，对高信心分布过松。这正是 top-p 想解决的问题。
IV.

top-p（nucleus）：边界跟着分布走

top-p（又叫 nucleus sampling，Holtzman 等 2019）把排序后的 token 累加概率，直到累积值超过 p，截止点之后全部 mask。p=0.9 的语义是「保留累积质量前 90% 的核」——保留几个 token 不固定，因分布而异。

这就是它比 top-k 更聪明的地方：高信心分布下保留少（也许 1-2 个就过 90%），低信心分布下保留多（可能要 15 个才到 90%）。它自适应于分布的峰度。

V.

min-p：相对置信度的过滤

min-p（Nguyen 等，2024 提出，2024 后半年开始在 vLLM / llama.cpp 默认开启）解决了 top-p 在高温度 / 低信心场景下的失控问题。它的规则极简：保留概率 ≥ min_p × p_top1 的 token。

换句话说，它用 top-1 的概率做尺子。min_p=0.05 的意思是：「只有那些概率不低于头号候选 5% 的 token 才有资格被采样」。这样无论分布尖锐还是平坦，过滤标准都跟着 top-1 自动伸缩。

VI.

四把刀同时挥的真实场景

产线里没有人只用一个参数。常见组合：先 temperature 拉伸或压缩，再 top-k 兜底硬上限，再 top-p 切核，最后 min-p 守相对底线。顺序不可换——温度改变的是 logits 进入 softmax 的尺度，必须最先做；其余三个是对概率的 mask，谁先谁后只影响存活集合的求交。

back-of-envelope · 一次 decode step 的成本

以 Llama-3-70B 为例，vocab = 128 256。一次采样的额外开销，对比 forward 的成本：

Forward (decode, batch=1) FLOPs≈ 1.4 × 1011
Logits 张量大小（fp16）≈ 256 KB
Softmax + 全排序~ O(V log V) ≈ 2 × 106 ops
top-k partial sort (k=40)~ O(V log k) ≈ 7 × 105 ops
top-p / min-p mask~ O(V) ≈ 105 ops
采样总开销 / forward< 0.001%

采样的成本几乎可以忽略——这是为什么这四把刀应当被当作首要的产线调优旋钮，而不是最后才动的"无关紧要的细节"。

记住这五件事

  1. 温度调的是「第一名的统治力」。它形变 logits 的尺度，但不改变排名。所有其他刀都在它之后作用——所以温度先调，再调 mask 类参数。
  2. top-k 是绝对数字，不看上下文。它对高信心分布过松、对低信心分布过严。用它做"硬上限兜底"（k=40~50）就好，不要靠它做主切。
  3. top-p 让边界跟分布走。比 top-k 更优雅，但在高温度下会失控——分布拉平后，p=0.9 会把更多低质量 token 纳入核。
  4. min-p 用 top-1 做尺子。在高温度 / 创意场景下比 top-p 更稳；vLLM 已经内置，min_p=0.05 是常见起点，可作为产线默认值替代 top-p。
  5. 采样成本可以忽略，但对输出质量的杠杆远超你的直觉。在 fine-tune 之前，先把 sampling 旋钮调过一轮——这是产线最高 ROI 的优化入口之一。
