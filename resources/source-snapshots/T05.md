# T05 可验证事实清单（Source Snapshot）

## 1. 已确认事实

### TensorRT-LLM Disaggregated Serving

来源：https://nvidia.github.io/TensorRT-LLM/features/disagg-serving.html

- prefill 与 decode 可分离部署
- 分离部署需要跨实例传递 KV cache

### NVIDIA Dynamo Introduction

来源：https://docs.nvidia.com/dynamo/v1.0.0/getting-started/introduction

- Dynamo 面向分布式推理服务
- 覆盖 disaggregated serving、KV-aware routing、KV offloading

### vLLM Ascend Plugin Documentation

来源：https://docs.vllm.ai/projects/ascend/en/main/

- vLLM-Ascend 以硬件插件方式接入 Ascend NPU
- 文档覆盖安装、功能矩阵、推理能力与开发指南

### MindIE LLM Introduction

来源：https://www.hiascend.com/document/detail/en/mindie/230/LLMframe/llmdev/mindie_llm0001.html

- MindIE LLM 面向昇腾大模型推理
- 文档列出 Continuous Batching、PageAttention、FlashDecoding 等推理能力

### vLLM-Ascend Supported Features

来源：https://docs.vllm.ai/projects/ascend/en/main/user_guide/support_matrix/supported_features.html

- vLLM-Ascend 功能矩阵用于判断推理特性支持情况
- 覆盖 prefix cache、chunked prefill、量化、并行等能力

## 2. 关键边界与版本说明（核验补充）

- NIXL 属 NVIDIA/CUDA 生态（走 NVLink/IB/UCX），HCCL 属昇腾 CANN 生态（NPU↔NPU，常经 Mooncake/ADXL 连接器）。同一部署的 KV 传输链路只会二选一，二者不会共用同一条链路。
- KV-aware routing 是“选 worker”的路由决策层，不是传输通道本身。
- vLLM-Ascend 图模式当前为 ACLGraph（默认）/XliteGraph，旧的 torchair graph mode 已在新版本移除（以 release notes 为准）。
- MindIE 的 PD 分离仅 Atlas 800I A2 支持，且官方文档明确 PD 分离不支持与 Prefix Cache / Multi-LoRA / SplitFuse 等同时使用。
- 来源：vLLM-Ascend disaggregated-prefill 设计文档、vLLM-Ascend release notes、MindIE PD 分离特性文档（见 sources 映射）。

## 3. 当前 demo 的教学假设

- 指标数值用于交互教学演示，不代表任何真实集群 benchmark。
- 动画中的 block、tile、worker 数量为概念示意，真实部署需以硬件、版本和流量画像实测为准。
